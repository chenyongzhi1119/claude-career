# 入门学习资料推荐

为用户想学的方向找到当前真正优质、未过时的入门资源，并组织成可执行的学习路径。

参数：`$ARGUMENTS`（方向名称，如"大模型应用开发"、"Go 后端"、"数据工程"）

## 流程

### 第 1 步：澄清（仅在必要时）
如果方向太宽泛（如只说"AI"），用 AskUserQuestion 确认具体分支和用户当前基础（零基础 / 有编程基础 / 相邻领域转入）。方向已经明确就直接开始，不要多问。

### 第 2 步：检索，不要凭记忆
必须用 WebSearch 检索最新资料（技术领域资料过时很快）。多角度搜：
- `<方向> 入门 教程 2026`（中文社区：知乎、掘金、B站）
- `<direction> roadmap / best resources for beginners`（英文：roadmap.sh、GitHub awesome 列表、Hacker News 讨论）
- 该方向核心技术的官方文档 / 官方教程
- 对重点推荐的资源，用 WebFetch 打开确认仍然有效、内容确实是入门级。

### 第 3 步：筛选标准
- 优先：官方文档、免费公开课、高 star 的开源教程、社区口碑一致的书。
- 剔除：内容基于已过时版本的教程、需要付费但有同等免费替代的、明显营销号内容。
- 中英文资源都要有；英文资源注明是否有中文翻译/字幕。

### 第 4 步：产出
输出一份完整交付物：

1. **方向速览**：这个方向做什么、就业面如何、和用户现有背景的衔接点（2-3 句）。
2. **资源清单**（按类型分组，每个资源一行说明"适合谁 + 为什么推荐"）：
   - 官方文档 / 官方教程
   - 系统性课程（免费优先，标注时长）
   - 书籍（1-2 本即可，标注读到哪几章算入门完成）
   - 实战项目参考（教程式项目或 GitHub 模板）
3. **最小可行学习路径**：
   - 第 1-2 周：做什么、用哪个资源
   - 第 1 个月：做什么
   - 验收标准：做出一个什么样的小项目/通过什么自测，就算入门完成
4. **常见弯路提醒**：这个方向初学者最容易犯的 2-3 个错误（如"只看视频不动手"、"一上来啃源码"）。

### 保存
问用户是否保存为 Markdown（默认 `~/Documents/career/学习路径-<方向>.md`）。

## 原则
- 每个推荐都要有出处（搜索验证过），给出链接。
- 宁可少而精（每类 2-3 个），不要堆砌 20 个链接让用户选择困难。
- 中文输出。
